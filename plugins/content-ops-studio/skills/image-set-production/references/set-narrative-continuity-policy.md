# Set narrative and continuity policy

This policy is industry-neutral. It transfers reusable full-set production discipline without importing any specific industry's scenes, brand signature, price rules, audience, area, material style or business claims.

## One system, different pages

A formal image set is one coherent editorial world, not one image repeated and not unrelated attractive images collected together.

Lock one set-level visual motif and at least three continuity anchors. Depending on the content, anchors may cover Subject identity, product identity, space identity, palette, light direction, material language, typography, grid logic, image treatment or recurring graphic devices. Every page must visibly retain at least two applicable anchors.

At the same time, every page must add a new semantic responsibility and a materially different visual contribution. A new headline, crop, overlay, exposure, zoom, Zone label or composition wrapper cannot turn duplicate source pixels into a new background.

## Page duties

- `COVER_CLICK`: page 1 creates one truthful click reason and the strongest mobile-first visual entry. It does not define the exact coordinates for later pages.
- `VALUE_DELIVERY`: every middle page delivers a distinct part of the approved promise. It may explain a problem, scenario, misconception, mechanism, evidence, comparison, step or solution, but may not become generic filler.
- `SUMMARY_CONVERSION`: the final page first gives a useful conclusion, self-check, decision path or next step, then uses only the approved conversion language. It is not a blunt CTA-only poster.

Page roles remain content-dependent. Do not force one universal sequence such as problem → causes → advice → CTA. The duties define responsibilities, not a fixed template.

## Background and shot planning

Each page declares one policy:

- `DISTINCT_BACKGROUND_REQUIRED`: scene/editorial/lifestyle pages must use a unique source raster checksum. Different crops of one master fail.
- `REUSE_WITH_MATERIAL_TRANSFORMATION`: only for evidence or another channel where the same authorized source must be revisited to reveal materially different information. The transformation and new evidence must be explicit.
- `NO_RASTER_BACKGROUND`: Pure Typography or precise Programmatic Graphic pages do not claim a background source.

For raster pages, plan a shot signature before generation or selection. The signature captures the actual visual contribution: viewpoint/axis, shot scale, spatial node or subject state and visual focus. Same-axis forward/backward movement, minor reframing, simple zooming and near-identical crops do not count as different shots.

When one real-world project, Subject, character or product must continue across pages, generate or select a coherent asset sequence: establishing context, transition or relationship view, functional/behavioral view, detail/evidence view and resolution view as appropriate. Preserve identity anchors while varying viewpoint, scale and semantic purpose.

## Typography and layout

Keep the set's font family, weight logic, palette logic, spacing discipline and Renderer ownership stable. Layout regions, composition family, crop, visual intensity, information density and image/text ratio may vary by page role. Cover attention devices and Cover-scale type must not be mechanically copied to content pages.

All core text must remain readable at actual mobile thumbnails. Magazine whitespace never justifies unreadable approved copy. Do not use white cards, rounded UI blocks or generic presentation layouts as a fallback for weak image-text integration.

## Hard blocks

- duplicate source checksum under `DISTINCT_BACKGROUND_REQUIRED`;
- same or near-identical shot signature across raster pages;
- visual-system key drift;
- missing continuity anchors;
- duplicate semantic responsibility or filler page;
- unfulfilled Cover, Value Delivery or Summary/Conversion duty;
- content page that stops delivering the Cover promise;
- closing page with only a command and no useful resolution;
- unreadable core copy at actual mobile size;
- a high aggregate score used to compensate for any of the above.

Passing produces only `PASS_PENDING_OPERATOR`. It never auto-approves G5.
