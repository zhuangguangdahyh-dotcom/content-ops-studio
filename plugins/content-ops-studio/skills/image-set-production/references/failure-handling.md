# Failure handling

Retain every attempt, checksum, QA result and successful artifact. Never overwrite an approved or historic asset, delete a failed attempt, or promote a technically failed PNG to a formal path.

Production recovery budgets are category-specific: Text Layout at most three attempts, Raster Contrast at most three attempts and Determinism at most two attempts. Each attempt records the changed variable and reason. Generated-visual recovery remains at most three materially targeted attempts and never runs when the frozen source is healthy. Stop earlier for safety, authorization, identity, evidence, format or capability blocks.

Determinism failure first verifies input hash, asset ordering, render seed, pinned context, font/image readiness and stable geometry. It then retries with a new equivalent context; it never mutates the first capture page. Text Layout failure follows the ordered recovery sequence and may not reduce below the declared minimum font size or change approved copy. Raster Contrast failure first moves or recolors text/graphics locally or adjusts local value; it may not replace the selected direction or visual-system key. Copy/Graphic failure reclassifies only truly decorative markers; semantic additions require a Copy revision and cannot be hidden as graphics.

When a budget is exhausted, return `MANUAL_OR_UPSTREAM_REVISION_REQUIRED`, preserve the Run and rework only the failing page unless Group QA proves a systemic direction failure. Never fabricate a successful path.
