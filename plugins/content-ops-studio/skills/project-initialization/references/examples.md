# Examples

- “Create a new project” → DISCOVER, plan, then explicit PROVISION.
- “Use the active project for audience research” → DISCOVER only current material gaps; if none, report research-ready without repeating the original questionnaire.
- “The Subject changed its core service” → UPDATE and `CONFIG_UPDATE_REQUIRED`; do not reuse stale confirmation.
- “Check whether the workspace drifted” → INSPECT + VERIFY, no write.
- “Restore the missing view” → REPAIR dry-run, then confirmed add-only write.
- “Change the field model” → UPDATE, set `CONFIG_UPDATE_REQUIRED`, prepare an approved MIGRATE plan; never silently replace the field.
