# Content Duplication Policy

Exact duplication uses a stable SHA-256 fingerprint over the primary Painpoint ID, angle, core viewpoint, Cover hook, structure and conclusion. Inputs are normalized with Unicode NFKC, case folding, line-break/whitespace normalization and punctuation removal.

Near-semantic risk is a retained Host assessment, not a fabricated embedding result. `HIGH` risk blocks finalization; `MEDIUM` requires a recorded distinction; `LOW` may proceed. Same-Painpoint alternates are allowed only when the angle or conclusion is materially different.

An identical idempotent replay is recovery, not duplication, and must reuse the same record. A different request that produces the same fingerprint is blocked as an exact duplicate. The system never solves a duplicate by deleting or silently overwriting the earlier Content.
