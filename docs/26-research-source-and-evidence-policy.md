# Research Source and Evidence Policy

Painpoint research starts from a confirmed Project Profile and a Run-bound plan. The production default request is 30, but the Runtime must return a lower evidence-backed count with an insufficiency reason instead of padding results with duplicates or hypotheses.

The Host acquires current public sources and submits bounded summaries, claims, limitations and citation locations. The MCP server normalizes safe HTTPS or project-relative locations, strips tracking parameters, computes content hashes and rejects unsafe/private locations. Full web pages are not stored.

Candidates must describe the business scenario, Audience, decision stage, explicit need, deep anxiety, trigger, barrier, cost, content angles and Subject advantages. Every candidate references retained Evidence. Exact duplicates are deterministic; near-semantic similarity requires an explicit retained judgment and is never represented as an embedding result.

Finalization compiles 34 approved logical fields, prechecks the record unique key, writes only missing records through the configured Workspace Adapter, read-verifies every field, writes an audit log and checkpoint, and stops at G2. It never creates a Base, table or content record in Phase 3A.
