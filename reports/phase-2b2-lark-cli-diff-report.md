# Phase 2B.2 architecture and live contract delta

## Added

- Official CLI version/config contracts and exact tested 1.0.63 pin.
- `LarkCliRunner`, capability/version/auth models and `LarkCliWorkspaceAdapter`.
- AUTO/LARK_CLI/DIRECT_FEISHU/MOCK selection with no Production Mock fallback.
- User OAuth setup/status/login/logout/scopes commands.
- Six strict JSON Schemas, fixtures, generated types and ADR-0019.
- Production G1 approval routing through project lock, Journal, Write Log and Adapter verification.

## Live contract corrections

- Base create may omit `default_table_id`; the Adapter lists and resolves the single platform default table.
- Table metadata supplies the authoritative primary-field identifier for safe adoption when other platform defaults also exist.
- Record search requires `keyword`, `search_fields` and tuple-style filter conditions.
- Official record results can be columnar (`fields`, `data`, `record_id_list`) instead of row objects.
- View create may omit a view ID and expose the new view after a short eventual-consistency delay.
- Single-select record values can be returned as singleton arrays and are normalized only for field type 3.
- A remotely successful G1 update can outlive local readback failure; retry reconciles the already-active remote state without a duplicate update.

## Preserved

- The unchanged 4/141/5/4 Blueprint, logical keys and G1–G5 state model.
- Direct Feishu as an advanced explicit mode.
- Project lock, Journal, Write Log, Checkpoint, input fingerprint, read-after-write, orphan protection and add-only Repair.
- All platform extras and Operator data; no delete-based rollback.

## Observed platform additions

- Three first-table default fields were retained.
- Two bidirectional-link reverse fields were generated by the platform.
- Four platform default views coexist with four named Blueprint views.

## Deferred

- Attachment upload, Research Adapter, real image generation, Production Renderer, Playwright, formal MCP and publishing.
- Live maximum-batch and rate-limit behavior; the one-record sandbox did not exercise them.
- Direct Feishu live validation.

No Plugin version, license, Git remote or Git history was changed. One sandbox Base was created and intentionally retained for manual cleanup.
